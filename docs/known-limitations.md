# 현재 알려진 제한 사항

## 결제 연동

- 실제 결제 게이트웨이 어댑터가 없다.
- `PaymentGateway`는 빈 인터페이스이며 현재 서비스 흐름에 연결되지 않는다.
- 결제 완료·실패·취소 API는 외부 PG callback이나 webhook을 대신하는 시뮬레이션이다.
- 실제 카드 또는 계좌 정보를 받거나 저장하지 않는다.

## 재고 동시성

- 장바구니 추가와 주문 생성은 현재 재고를 검증하지만 예약하지 않는다.
- 재고는 결제 완료 시 차감한다.
- 상품 행에 명시적인 낙관적 버전이나 비관적 잠금이 없다. 동시에 같은 상품을 결제 완료하는 상황의 초과 판매 방지는 현재 보장하지 않는다.

## 인증

- access token만 사용하며 refresh token이 없다.
- token blacklist 또는 revocation 저장소가 없다.
- 로그아웃은 클라이언트가 token을 폐기하는 방식이다.
- 발급 이후 사용자 역할이 바뀌어도 다음 요청에서 사용자를 다시 조회하므로 현재 DB 역할이 적용되지만, 이미 발급한 token 자체를 개별적으로 폐기할 수는 없다.

## 운영과 배포

- 운영 배포 구성, CI/CD, 운영 환경별 설정이 없다.
- `application.yml`에 로컬 DB 자격 증명과 개발용 JWT secret이 고정되어 있다.
- Docker Compose는 로컬 MySQL 개발 환경만 제공한다.

## API와 기능

- 배송, 환불, 할인, 쿠폰, 결제 만료, 주문 자동 취소가 없다.
- 상품 삭제 대신 활성화·비활성화만 제공한다.
- HTML을 렌더링하지 않고 JSON만 반환한다. 사용자 입력을 HTML에 포함하는 기능이 추가되면 출력 인코딩과 XSS 정책을 다시 검토해야 한다.
